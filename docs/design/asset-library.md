# SunsetAsset の設計

アセット (モデル、テクスチャ、音、独自のデータ …) を取り込み、ID で管理し、変換した結果をキャッシュするライブラリ。
SunsetStudio の M5-3 (モデルの読み込み) から使い始める。エンジン (SunsetGraphicsEngine) にも GPU にも依存しない。

## 決まっていること (2026-10-19、ユーザーの決定)

| 項目 | 決定 |
|------|------|
| リポジトリ | SunsetAsset (単独のライブラリ。エンジン / MathLib と同じ扱い)。モデルとテクスチャだけでなく、音や独自のデータも扱える汎用のもの |
| 識別 | ID (GUID) + ファイルの隣の `<ファイル>.meta`。参照は ID で行うので、移しても名前を変えても切れない |
| キャッシュ | 取り込んだ結果は自前のバイナリ (版つき) にして `Cache/` に置き、元のファイルや設定が変わったら作り直す |
| モデルの範囲 (最初) | 静的なメッシュ、マテリアルのスロット、ノードの階層、マテリアルの情報。スキンとモーフも読んで保存する (描画はバインドポーズ)。変形とアニメーションは次の段階 |
| シーンでの扱い | 置いたモデル 1 体 = シーンの物体 1 つ。部品の階層はモデルの中に持ち、スロットにマテリアルを割り当てる |
| 形式 | FBX (Maya)、glTF / GLB (Blender) を最初に。PMX (MMD) はその次。音 (WAV / OGG など)、独自のデータはあと |
| 置き場所 (プロジェクト) | モデルとテクスチャはプロジェクトの `assets/` (中は自由に整理)。コピーが既定で、外部 (Maya / Blender の作業フォルダ) の参照もできる |

## モジュール

```
SunsetAsset::core      GUID、.meta、アセットのデータベース、取り込みの登録、キャッシュの入れ物
SunsetAsset::model     モデルの型と、FBX (ufbx) / glTF (cgltf) の取り込み          ← M5-3
SunsetAsset::texture   テクスチャの型と、PNG / JPEG / TGA (stb_image) の取り込み  ← M5-3
(のちに) SunsetAsset::audio、独自のデータは使う側のアプリが取り込みを登録する
```

- 外部のライブラリ (ufbx、cgltf、stb_image。どれも MIT など) は、それぞれのモジュールの中だけで使い、ヘッダーには出さない。
  取得は FetchContent (アーカイブの URL + SHA256 で版を固定)。
- 使う側は必要なモジュールだけをリンクする (音を使わないアプリに音のデコーダーを入れない)。

## .meta

アセットのファイルの隣に置く JSON。git で管理する (ID が変わると参照が切れるため)。

```json
// assets/chara/hero.fbx.meta
{
  "version": 1,
  "id": "3f2a1b4c5d6e4f708192a3b4c5d6e7f8",
  "importer": "model",
  "settings": { "scale": 1.0, "axis": "auto", "generateTangents": true }
}
```

- `importer` は取り込みの種類の名前。`settings` はその取り込みの設定 (既定値と違うものだけでもよい)。
- **外部の参照**: `assets/` に `.meta` だけを置き、`"source": "D:/work/hero.fbx"` で元のファイルを指す。
  元のファイルの変更を見て取り込み直し、見つからなければ印を出す。あとで「取り込む」でプロジェクトにコピーできる。
- ファイルを移すときは `.meta` も一緒に移す (Studio のアセットのパネルからの移動 / 名前の変更は両方を動かす)。
  エクスプローラーで `.meta` を置いて移すと新しい ID になり、参照が切れる (Studio は「見つからない ID」として印を出す)。

## データベース

- 起点のフォルダ (`assets/`) を走査し、`.meta` を読んで ID → パスの表を作る。
- 取り込みが登録されている拡張子で `.meta` のないファイルには、`.meta` を作る (新しい ID)。知らない拡張子は扱わない。
- 変更の監視は使う側が行う (Studio は今のホットリロードと同じく、更新時刻を見て取り込み直す)。

## 取り込みの登録

```cpp
class Importer {
public:
    virtual std::string_view name() const = 0;                  // "model"
    virtual std::span<const std::string_view> extensions() const = 0;  // ".fbx", ".gltf", ".glb"
    virtual uint32_t version() const = 0;                       // 変換の仕方を変えたら上げる (キャッシュを作り直す)
    virtual Json defaultSettings() const = 0;
    virtual bool import(const ImportContext& ctx, ArtifactWriter& out, Diagnostics& diag) = 0;
};
registry.add(std::make_unique<ModelImporter>());
```

- 使う側のアプリが、独自のデータの取り込みを登録できる (音や独自のデータも同じ仕組み)。
- 取り込みはスレッドから呼んでよい (状態を持たない)。

## キャッシュ

`Cache/assets/<id>.bin`。中身は版つきの入れ物 (チャンクの並び)。

| 部分 | 内容 |
|------|------|
| ヘッダー | 目印 `SAST`、入れ物の版、取り込みの名前と版、元のファイルの大きさと更新時刻とハッシュ、設定のハッシュ |
| チャンク | (4 文字のタグ、大きさ、中身) の並び。モデルなら `NODE` `MESH` `SLOT` `SKIN` `MRPH` … |

ヘッダーのどれかが今と違えば作り直す。入れ物の形は種類によらず共通で、読むのは種類ごとの関数 (`loadModel` など)。

## モデルの型 (取り込んだ結果)

座標は **右手系、Y が上、単位はメートル** (ビューポートと同じ)。FBX は ufbx で単位と軸を変換する (Maya の cm → m など)。
glTF はもともと同じ。`.meta` の `scale` / `axis` で上書きできる。

| 部分 | 内容 |
|------|------|
| ノード | 名前、親、ローカルの位置 / 回転 (クォータニオン) / 大きさ、メッシュの番号 (なしも) |
| メッシュ | 頂点の列: 位置 float3、法線 float3、接線 float4 (なければ作る)、UV0 / UV1 float2、色 float4、スキン (骨の番号 u16×4、重み float×4)。インデックス u32。サブメッシュ (インデックスの範囲 → スロットの番号)。境界の箱 |
| スロット | 名前 (シーンでマテリアルを割り当てるときの鍵)、マテリアルの情報 (基本色、金属 / 粗さ、発光、不透明 / 半透明、テクスチャのパス: 色、法線、金属粗さ、遮蔽、発光) |
| スキン | 骨 (ノードの番号)、逆バインド行列 |
| モーフ | メッシュごとの名前と差分 (位置、法線) と、既定の重み |

- GPU の形 (頂点バッファの並び) にはしない。どう GPU に載せるかは使う側 (Studio) が決める。
- テクスチャのパスは、取り込みのときに `assets/` の中のテクスチャの ID に解決する (なければパスのまま残して印)。

## テクスチャの型

RGBA8 (または 1〜4 チャンネル) の画素、幅 / 高さ、色空間 (sRGB / リニア。`.meta` の設定、既定は用途から推測)。
mip の生成と圧縮 (BC7 など) は後の段階。HDR (`.hdr` / `.exr`) も後。

## SunsetStudio での使い方 (M5-3)

1. Studio は SunsetAsset を FetchContent で取り込む (開発用のプリセットでは隣のフォルダ)。
2. **アセットのパネル**: `assets/` の一覧 (種類、取り込みの状態、エラー)。「取り込む…」でファイルを選び、`assets/` にコピー (または外部の参照) して `.meta` を作る。
3. モデルをシーンに置く: シーンの物体の `model` を `"asset:<id>"` にする (`builtin:cube` は今のまま)。
4. 描画: 取り込んだモデルから頂点 / インデックスバッファを作り、サブメッシュごとに描く。スロットの色は、マテリアル (M5-4) までの仮として、取り込んだ基本色を使う。スキンのあるモデルはバインドポーズで描く。
5. 選択: 今の箱の判定を、モデルの境界の箱で行う。

## テスト

- core: GUID、.meta の読み書き、データベースの走査 (`.meta` を作る、ID → パス、重複した ID の扱い)、キャッシュの入れ物 (版の違いで作り直す)。
- model: 小さな glTF をテストの中で書いて取り込む。FBX はテスト用の小さな ASCII FBX をリポジトリに置く (自作)。ノード、サブメッシュ、スロット、スキン、モーフ、単位と軸の変換を確かめる。
- texture: 小さな PNG / TGA をテストの中で作って読む。

## S2 の実装

| 項目 | 内容 |
|------|------|
| 取り込みの登録 | `makeModelImporter()` ("model": .fbx / .obj / .gltf / .glb)、`makeTextureImporter()` ("texture": .png / .jpg / .jpeg / .tga / .bmp)。読むときは `loadModel` / `loadTexture` (キャッシュのファイルから) |
| キャッシュの形 | モデル: `MJSN` (構造の JSON: ノード、スロット、スキン、メッシュの名前 / 頂点の数 / サブメッシュ / 境界 / モーフの名前と、配列の位置) と `MBIN` (配列を並べたもの)。テクスチャ: `TXIN` (幅、高さ、チャンネル、sRGB) と `TXPX` (RGBA8) |
| glTF | 座標はそのまま。primitive をつなげて 1 つのメッシュにし、primitive ごとにサブメッシュ (スロット = マテリアル。マテリアルのないものは "Default")。行列で書かれたノードは位置 / 回転 / 大きさに分ける。モーフはメッシュの target_names / weights。ファイルは自前で読んで cgltf に渡す (UTF-8 のパス) |
| FBX / OBJ | ufbx に、外部のファイル (OBJ の .mtl) を読む、右手系 / Y が上 / メートル、ジオメトリの変換をメッシュに焼き込む、足りない法線を作る、を頼む。面を三角形に分け、同じ頂点はまとめる。マテリアルの部分ごとにサブメッシュ。UV は上下を反転 (左上が原点)。スキンは最初のスキンのクラスタ (逆バインド = geometry_to_bone)。ブレンドシェイプはチャンネルごとにモーフ |
| 共通 | 骨の重みは大きい 4 つを残して合計 1 に。接線は UV0 があれば作る (三角形ごとに足して法線に直交させる。MikkTSpace ではない)。境界の箱 (メッシュごと、モデル全体) |
| 設定 | model: `scale` (1.0)、`generateTangents` (true)。texture: `srgb` (true) |
| 参照するファイル | `Importer::referencedFiles` (テクスチャ、glTF の .bin、OBJ の .mtl)。Studio がプロジェクトに取り込むとき、一緒にコピーする |
| 取得 | ufbx はアーカイブがテストデータ入りで CMake の展開に失敗するので、タグの `ufbx.h` / `ufbx.c` を SHA256 付きで個別に取得する |
| テスト | glTF (テストの中で書く: 2 つの primitive、2 つのマテリアル、スキン、モーフ、ノードの階層、`scale`)、FBX (手書きの ASCII: cm → m、マテリアル)、OBJ、壊れたファイル、TGA |
| 未対応 | 埋め込みのテクスチャ (glTF の data URI / bufferView、FBX の content)、glTF の疎な accessor の確認、MikkTSpace の接線、テクスチャの mip / 圧縮 / HDR |

## S4 の実装 (PMX / PMD)

| 項目 | 内容 |
|------|------|
| 取り込み | `src/model/PmxImport.cpp` (自作)。拡張子 `.pmx` (2.0 / 2.1) / `.pmd`。モデルの取り込み ("model") の版を 2 に上げた (extras のため、キャッシュを作り直す) |
| 座標 | Z を反転 (位置、法線、モーフの差分、骨の位置、剛体 / ジョイントの位置)、三角形の向きを入れ替える。回転 (オイラー角) と回転の範囲は X / Y を反転、クォータニオンは (-x, -y, z, w)。1 単位 × 0.08 (設定の `scale` も掛け、剛体などの extras にも掛ける) |
| 頂点 | 1 つのメッシュ、MMD の頂点の番号のまま (同じ頂点をまとめない。モーフの番号と合わせる)。UV は左上が原点のまま、追加 UV 1 の xy を UV1 に。重みは BDEF1 / 2 / 4 はそのまま、SDEF → BDEF2、QDEF → BDEF4 (警告)。接線は作る |
| 材質 | スロット: 名前、基本色 = 拡散色 + アルファ (1 未満なら Blend)、両面、テクスチャ、粗さは反射の鋭さからおおよそ。`extras.mmd`: 反射色 / 鋭さ / 環境色、トゥーン (個別のファイル、または共有の `toonNN.bmp`)、スフィア (乗算 / 加算 / サブテクスチャ)、輪郭線 (有無 / 色 / 太さ)、影の設定 (地面影 / セルフ影)、メモ |
| 骨 | ノード 0 はメッシュ (スキン 0)、骨はノード 1 から (位置は親からの相対、回転なし)。スキンの骨 = 全部の骨、逆バインド = 骨の位置を戻す。`extras.mmd` (ノード): 英語名、変形の階層、フラグ、先端、付与親 (親 / 割合 / 回転 / 移動)、軸の固定、ローカル軸、外部の親、IK (対象 / 回数 / 制限角 / リンクと角度の範囲)。骨の番号はノードの番号にしてある |
| モーフ | 頂点モーフはメッシュのモーフ (差分を全頂点に広げる)。グループ / 骨 / UV / 追加 UV / 材質 / フリップ / インパルスは `Model::extras.mmd.morphs` に保存だけ |
| 物理など | 表示枠、剛体 (形 / 大きさ / 位置 / 回転 / 質量 / 減衰 / 反発 / 摩擦 / モード)、ジョイント (位置 / 回転 / 移動と回転の範囲 / ばね) は `Model::extras.mmd` に保存だけ。PMX 2.1 のソフトボディは読まない。後ろが切れていたら警告して、読めたところまで使う |
| PMD | Shift_JIS の名前 (Windows の変換。ほかの OS では ASCII 以外を ? に)。材質のテクスチャ欄の "tex*sphere" を分ける。表情は base の表で頂点に戻す。英語名、トゥーンのファイルの表、剛体 (骨からの相対の位置)、ジョイントを読む。IK はモデルの extras に |
| 参照するファイル | テクスチャ、スフィア、個別のトゥーン (共有のトゥーンは含めない) |
| テスト | `tests/test_mmd.cpp`: PMX (4 種類の重み、2 材質、IK と付与親の骨、頂点 / グループ / 骨のモーフ、表示枠、剛体、ジョイント) と PMD (Shift_JIS、テクスチャ * スフィア、表情、トゥーンの表) をテストの中でバイト列で書き、座標の変換、三角形の向き、extras、`scale`、参照するファイル、壊れたファイルを確かめる |
| 未対応 | ボーンの回転のある姿勢 (MMD の骨は回転を持たないので不要)、SDEF / QDEF の正確な変形、ソフトボディ、材質の描画 (トゥーン / スフィア / 輪郭線を使う「描画クラス」は Studio の側で) |

## 確認済み (2026-10-19、ユーザーの決定)

1. 単位と軸の既定は、メートル / Y が上 / 右手系。Maya の cm は m に変換する (100 cm = 1 m)
2. 取り込みのときに、FBX / glTF が参照しているテクスチャも `assets/` へ一緒にコピーする (外部の参照のときはコピーしない)
3. ライセンスはエンジンと同じく未決のまま (LICENSE ファイルなし)
